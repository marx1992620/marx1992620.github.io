數據分析＆AI建模 DA&MLE

  • 逾時瓶頸來自特徵存取而非模型運算；重構風險評估之資料結構與存取路徑後，模型逾時率 −95%
  • 經濟部智慧創新競賽第一名：即時信用卡交易與帳戶登入詐欺偵測，涵蓋盜刷與帳戶接管（ATO）
  • 製造業期間之建模成果：品質預測準確率 88%、安全庫存與庫存成本 −69%、機台預測一年份運算 95hr→7min

數據工程 DE

精簡鏈路層級，逾時歸零

Pipeline 重構串流處理 資料庫選型資料治理
  • 資料流重構：DB→Debezium→Kafka→Logstash 改為 AP→Kafka→Flink→Doris，少兩層中介，逾時率 4.1% → 0%
  • Redis list → zset（skip-list + hash），插入 O(N)→O(logN)，刪除耗時 125.6s → 2.1s；zset 與 RedisGraph 節點改非同步刪除
  • 導入 DataHub：原欄位定義散於 schema、評分邏輯位於他表、權責記載於程式碼，建立資料目錄、字典、血緣圖與權限歸屬後，資料來源、演算法與負責人均可追溯，符合金融合規要求
  • Redis／MySQL／Doris／Lakehouse 逐項評估，依 OLTP 或 OLAP 之實際存取型態選型；分析型查詢改用 Doris 後處理效率明顯提升

系統維運 SE

先界定優化範圍，再投入資源

客戶端駐點AWS 雲端服務 K8s 服務維運壓力測試
  • 到職期間小主管、技術負責人、資料與系統工程師相繼離職，主動承接其負責之服務，重新釐清架構與資料流並將維運知識文件化；期間客戶端服務維持 0 中斷，並同步完成效能優化
  • 雙 11 尖峰 TPS 150：Lua/EVALSHA、io-threads 調參、hash-slot keying 平衡圖節點、Predixy／HAProxy 讀寫分離，逾時 12.5% → 0.9%
  • JMeter 壓測拆解 RT 與 RTT，把優化切成模型內部／外部 IO／系統三層；搭配 KEDA 事件驅動擴縮容，TPS +137%
  • Wipro 期間駐點客戶端：整合資料管線覆蓋率 99%，替 40+ 位工程師省下 50% ETL 與驗證工時

專案管理 PM

以風險與成本說明方案，取得客戶採用

客戶溝通時程規劃 架構方案提案銀行客戶對接
  • 提出雙站點 Active-Active 架構方案，逐層推導各資料層不同步對服務之實際影響：Redis 不同步致模型準確度下降、PostgreSQL 不同步致推論失準、Elasticsearch 不同步致監控與學習系統同時缺料，並逐項提出解法與成本評估
  • 直接與國內外銀行客戶確認部署時程與驗收標準，把工程排程對齊客戶的上線窗口
  • 與客戶共同訂定驗收標準，由單看模型指標改以可接受誤攔上限定義，模型自參考數據轉為線上攔阻決策依據
  • 撰寫三份導入計畫書：AI 客服系統、資料治理架構、服務效能優化 Scope
